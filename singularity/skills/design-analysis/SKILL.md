# design-analysis — макет → design-brief с числами

Один из двух скилов Этапа 1 с легитимным LLM-суждением (эстетика). Правило: **каждое суждение цитирует число** из инструментов; free-form оценки «на глаз» запрещены (контраст «на глаз» уже ошибался: 4.2 vs реальные 4.93).

> **Правило нулевого кода:** размеры/палитру/границы секций считает `design-metrics.py`, прозрачность/формат — `imgqa probe`, контраст пар — `imgqa contrast`. Новых скриптов — 0.

## Порядок

```bash
# 1. Техконтекст макета (формат, alpha, не запечённая ли шахматка)
imgqa probe MOCKUP.png --json

# 2. Числа: размеры, aspect, доминантная палитра, кандидаты секций
E:\Singularity\.venv\Scripts\python.exe \
  "E:\Singularity\singularity\skills\design-analysis\scripts\design-metrics.py" \
  MOCKUP.png --out "<evidence-dir ВНЕ дерева макета>" --json

# 3. Мультимодальный Read макета — суждение ПОВЕРХ чисел шага 2
# 4. Ключевые цветовые пары текста — imgqa contrast (числа в бриф)
```

## Методика разбора (шаг 3)

- **Секции:** `data.bands` — кандидаты границ по смене цвета строк. Суждение: склеить/разделить кандидатов по смыслу (band ≠ секция автоматически), каждой секции — top/bottom/height/share_pct из bands.
- **Пропорции:** `aspect_h_over_w` макета — якорь для fidelity (прецедент NIKA: макет 1.78×, реализация 5.09× — категория A-дефект «вертикально раздуто»).
- **Палитра:** `dominant_colors` (hex+доля) — это фон/атмосфера; акцентные цвета мелких элементов брать пипеткой мультимодально и ПОДТВЕРЖДАТЬ парой через `imgqa contrast`.
- **Типографика:** шкала (display/heading/body/caption) описывается ОТНОСИТЕЛЬНО (в долях высоты секции), не абсолютными px «на глаз».
- **Композиционные акценты:** перекрытия, диагонали, visual stage; отмечать «что держит секцию» (урок NIKA hero: phone overlap — art-directed stage, не flow).

## UNVERIFIED — жёсткий гейт

Весь ТЕКСТ и данные макета (цифры, цены, отзывы, имена, контакты) — art-direction, НЕ факты. В брифе каждый такой элемент помечается `UNVERIFIED` и уходит владельцу списком вопросов. Truth-gate урок NIKA: «можно ли считать макет фактическим контентом? — нет». design-metrics.py намеренно не извлекает текст.

## Формат design-brief (выход)

Заметка (vault или evidence-dir) с разделами: 1) Источник + числа (dims/aspect/палитра — из metrics.json); 2) Секции (таблица: имя, top-bottom, height, share%, назначение); 3) Типографика (шкала, относительная); 4) Цвет и контраст (пары + ratio из imgqa); 5) Композиционные акценты; 6) UNVERIFIED-контент → вопросы владельцу; 7) Приоритеты для реализации.

Бриф обязан быть пригодным входом для [[design-fidelity-audit]]: числа брифа = эталон A/B-категоризации.

## Гейты

- [ ] `schema` = `design-metrics/1`; exit 2 = инструмент не отработал.
- [ ] Ни одного размера/цвета в брифе без ссылки на metrics.json/imgqa вывод.
- [ ] UNVERIFIED-список — всегда, даже пустой («UNVERIFIED: нет» — явная строка).
- [ ] Бриф принимает владелец (human gate) до старта вёрстки.
