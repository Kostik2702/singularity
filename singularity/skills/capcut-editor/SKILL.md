# capcut-editor — ЛЕГАСИ

> **Заменён стеком `bridge-montage`.** Для любой новой работы с CapCut использовать его:
> `bridge-montage` (оркестратор) → `bridge-framing`, `bridge-rhythm`, `bridge-build`,
> `bridge-cost`. Бэкенд — CapCut Bridge (`E:\Project\capcut-bridge`), собственный, с
> каталогом ресурсов, журналом операций и readback.
>
> **Кандидат на удаление.** Всё уникальное перенесено:
> `references/draft-safety.md` → `bridge-build/references/draft-safety.md`;
> `references/plan-schema.md` → `bridge-framing/references/shot-list.md`;
> `references/mcp-contract.md` (уровни доказательности, семантика операций) →
> `bridge-build/references/api-map.md`.
> Ценность остатка — только как описание того, что делал прототип `mcp__capcut__*`,
> если придётся разбирать собранные им проекты.
>
> Причина замены: прототип держал ресурсы замороженными enum-таблицами (из 197 ресурсов,
> реально использованных в проектах, в них было 4), не писал карточку проекта, возвращал
> `False` на упавшей загрузке и молча удалял пересекающийся сегмент.

Собрать **редактируемый CapCut draft**, а не только финальный видеофайл. Работать
через доступный CapCut MCP и его публичные tools. Не редактировать внутренний JSON
draft вручную и не подменять отсутствующий MCP командами reel/ffmpeg.

Перед первой операцией прочитать references/mcp-contract.md. Для существующего
проекта дополнительно прочитать references/draft-safety.md. До записи составить
план по references/plan-schema.md.

## Workflow

### 1. Capability preflight

- [ ] Перечислить доступные CapCut MCP tools и сопоставить их с capability matrix из references/mcp-contract.md.
- [ ] Выбрать профиль: general-draft, talking-head или unsupported; не выводить профиль из названия сервера.
- [ ] Проверить все capabilities, необходимые именно текущему плану. При нехватке хотя бы одной вернуть список отсутствующих операций и остановиться.
- [ ] Зафиксировать provider/server, версию или commit, если доступны, и корневой каталог drafts.

### 2. Intake и метод

- [ ] Определить: новый проект или изменение существующего; sources и draft root; canvas/fps; длительность; музыка/голос; copy/captions; must-use/must-avoid; целевую платформу; media policy link или copy.
- [ ] До первого творческого решения выполнить mb search по задаче. Метод брать из vault: Short-form монтаж _ MOC, Базовый монтаж короткого ролика, Ритм и изменение темпа, Субтитры для вертикального видео, Антипаттерны short-form монтажа _ QA чек-лист.
- [ ] Не скачивать удалённые media URL и не публиковать/экспортировать ролик без отдельного разрешения владельца.

### 3. План до мутации

- [ ] Создать capcut-plan.json по references/plan-schema.md: backend provenance, media policy, все tracks, frame-quantized ranges, текст, captions, эффекты и keyframes.
- [ ] Проверить существование локальных источников, их длительности и отсутствие отрицательных/перекрывающихся диапазонов.
- [ ] Получить подтверждение владельца только для decision gates: canvas/crop с потерями, спорный порядок, финальный copy, замена/удаление материала.
- [ ] Не начинать MCP writes, пока план не полон и не воспроизводим.

### 4. Безопасная цель

- [ ] Для нового проекта создать уникальный draft; не переиспользовать существующее имя молча.
- [ ] Для существующего проекта применить references/draft-safety.md: CapCut закрыт, исходник зафиксирован, создан отдельный клон/backup, target path отличается от source path.
- [ ] Если MCP умеет только in-place mutation и не умеет безопасно клонировать/readback, остановиться; явное разрешение пользователя не отменяет обязательный backup.

### 5. Сборка

- [ ] Создать canvas/fps и добавлять элементы в порядке плана: picture → audio → text/captions → функциональные effects/keyframes.
- [ ] После каждого tool call проверить typed result/error; не продолжать после частичной ошибки как будто операция завершена.
- [ ] Сохранить новый draft только в согласованную target-папку.
- [ ] Не добавлять декоративный эффект, если его функцию нельзя назвать одним предложением.

### 6. Проверка и handoff

- [ ] Выполнить лучший доступный readback по уровням evidence из references/mcp-contract.md; сравнить canvas, fps, длительность, tracks и количество элементов с capcut-plan.json.
- [ ] Для клона доказать, что source draft не изменился после начала операции.
- [ ] Попросить владельца открыть target draft в CapCut и просмотреть целиком со звуком, без звука и с интерфейсными safe zones.
- [ ] Вернуть draft path, capability profile, краткую timeline-сводку, evidence, ограничения, внешние media dependencies и оставшиеся ручные действия.
- [ ] Новое неочевидное сохранить через mb learn --task <ID>.

## Stop conditions

- [ ] Нет совместимого CapCut MCP или обязательного tool — STOP, не имитировать результат.
- [ ] CapCut открыт во время локальной draft-мутации — STOP, попросить закрыть приложение; не завершать процесс самостоятельно.
- [ ] Source и target draft совпадают — STOP.
- [ ] Tool не даёт различить success и partial failure — STOP до проверки результата.
- [ ] Draft открывается только после ручного ремонта JSON — считать операцию failed; внутренний формат не чинить из скилла.
