# Draft safety

Применять при любом изменении существующего CapCut project/draft.

## State machine

DISCOVERED → PLANNED → SAFE_TARGET → WRITTEN → VERIFIED → OWNER_ACCEPTED

Переходить дальше только с evidence предыдущего состояния.

## Pre-mutation

- [ ] Разрешить абсолютный source draft path и убедиться, что это один проект, а не весь drafts root.
- [ ] Проверить, что процесс CapCut не запущен. Попросить владельца закрыть приложение; не завершать процесс автоматически.
- [ ] Записать source manifest: относительные пути, размеры и mtimes; metadata/JSON-файлы дополнительно захешировать.
- [ ] Создать target с новым именем вида name-ai-timestamp через MCP clone/copy capability.
- [ ] Проверить, что target существует, source != target и target не был ранее существующим проектом.

Если provider не умеет clone/copy безопасно, разрешается обычная файловая копия
только после точного разрешения source/target и только средствами одного shell.
Нельзя вручную менять draft JSON, чтобы адаптировать копию.

## Post-mutation

- [ ] Повторить source manifest и доказать отсутствие изменений.
- [ ] Проверить target readback или typed save result.
- [ ] Не удалять failed target автоматически: вернуть его путь и статус.
- [ ] Не считать открытие проекта в CapCut доказанным без человеческого просмотра.

## Existing-project policy

Явная просьба «измени мой проект» разрешает изменение содержания, но по умолчанию
не разрешает in-place запись. In-place допустим только после отдельного прямого
подтверждения и всё равно требует проверенного backup, который не меняется в ходе
операции.
