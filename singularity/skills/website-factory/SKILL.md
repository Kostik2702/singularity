# website-factory — a pipeline, not inspiration

The canonical route: vault [[WEBSITE-FACTORY-E09-STATE-GRAPH]] (S1-S10). The orchestrator does NOT invent steps — it drives along the graph, where each stage is an existing tool with a typed output, and **stops at every human gate**. The resume point of any stage is its output file; a failed provider or stage does not zero the run.

> Before starting: `mb search "<project>"` (SEM-FIRST) — earlier decisions, budgets, brief. Every run is written into the project's learnings.

## The route (tool → output → gate)

| S | Action | Tool | Output (resume) |
|---|---|---|---|
| 0 | Brief contract from the owner | template §1 of decision v2 | brief note |
| 1 | Visual references | `design-scout collect` | moodboard.html → **⛔ owner** |
| 2 | Mockup analysis (if there is one) | design-analysis skill | design-brief → **⛔ owner** |
| 3 | Stack profile | `stackrouter` over `.factory/manifest.json` | recommendation; a profile change → **⛔ owner** |
| 3b | Scaffold | `starters/<profile>` (copy) + visual-regression-bootstrap skill | working skeleton + harness |
| 4 | Pattern candidates | `pattern-scout search --board --profile` | review-board.html → **⛔ owner shortlist** |
| 5 | Quarantine of each choice | `component-intake run --runtime` | intake-report; REJECT ends the branch |
| 6 | Recipe | `component-intake recipe --report` → pattern-adapter skill → `--validate` (exit 0) | recipe.json |
| 7 | Implementation | motion-3d-implementer skill (the project's feature branch) | code per patch_set |
| 8 | Quality gates | motion-qa (+ the project's budgets) · determinism checker · a11y-audit · fidelity-audit | reports; FAIL → iterate S7 (**cap 3**, then escalate) |
| 9 | Visual baseline + slice acceptance | — | **⛔ owner-only** (`test:update-baseline` is run by the owner) |
| 10 | Registry | `golden add` (candidate) → a 2nd application or the owner → `golden promote` | registry item |

Git discipline: every task gets a feature branch → merged into the epic/project when ready; engine changes go only through epic/website-factory.

## Orchestrator rules

- **Gates are not bypassed.** No owner answer → the stage waits; you may work on another branch of the graph (per-candidate independence). A draft default is allowed ONLY with an entry in decisions/ marked ⚠️draft (precedent [[WEBSITE-FACTORY-DRAFT-GATES-2026-07-19]]).
- **Typed or it did not happen.** A stage output with no envelope or file means the stage was not passed. exit 2 from any tool means fix the tool or the environment, not "skip it".
- **0 one-off scripts** (KPI WSF-13): everything already exists as subcommands; a new script is a regression of the pipeline.
- **A capability lives in the engine, a skill only routes to it.** A missing function is a change to a tool (`pattern-scout`, `component-intake`, `imgqa`, the harness), not one more script in the skill's folder. The precedent and its cost: 8 scripts of the `bridge-*` stack, 4 of which duplicated more mature subcommands, while 2 held a second copy of the crop geometry.
- **Licences:** unknown means reference-only at ANY stage; paid means report-only until the owner rules. The licence is read BEFORE recommending a candidate, not before vendoring; `NOASSERTION`/`Other` on GitHub means "not recognised" and is a reason to open `LICENSE`, not to treat the project as permissive.
- **The asset manifest is generated by walking the tree, never by hand:** the generator fails on any unaccounted or unexplained file (coverage self-check). A manual manifest drifts silently, and "100% coverage" becomes a lie on the very first file added; editing the manifest by hand is a code smell at review.
- **Run metrics** (for WSF-13/E10): time to shortlist / to the first section / to the build, PASS/ADAPT/REJECT, S7-S8 iterations, number of owner questions — into each run's learnings.
