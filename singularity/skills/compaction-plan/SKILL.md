# compaction-plan — сохранение состояния перед clear

Порт Genevra compaction-plan: полный план продолжения пишется в vault, новая сессия подхватывает его через SessionStart-hook (recall) и продолжает без потерь.

## Протокол

- [ ] 1. Собери состояние ТЕКУЩЕЙ сессии: активная задача и фаза workflow; что сделано (с file:line/путями); что осталось (конкретные следующие шаги, не «продолжить»); открытые решения/вопросы с owner; важные пути/команды/значения, добытые в сессии; незакоммиченные изменения (`git status --short`, сохрани как снимок — он понадобится на возобновлении для git-reconcile).
- [ ] 2. Запиши в `E:\obsidian\memory brain\compaction-plans\<YYYY-MM-DD-HHmm>-<task>.md` (frontmatter: type=reference, title, created, task, tags:[compaction]). Плотно, без пересказа диалога — только то, что нужно для продолжения. **Бюджет: ≤120 строк тела** (без frontmatter) — это одноразовый оперативный артефакт для возобновления, не отчёт о сессии; если не помещается, режь детали реализации (они и так в git diff), оставляй решения/следующие шаги/открытые вопросы.
- [ ] 3. Сообщи пользователю одной строкой: план сохранён, после clear новая сессия увидит его автоматически.

## На стороне возобновления (новая сессия)

- [ ] 1. SessionStart-hook показывает pending compaction-plans (имена файлов). Если пользователь говорит продолжить — переходи к шагу 2; если выбрал другую работу — план НЕ трогай, оставь до явного решения (не удаляй, не читай проактивно).
- [ ] 2. Прочитай ПОЛНЫЙ план + активный learnings-док задачи, на которую он ссылается (`task` из frontmatter).
- [ ] 3. **Reconcile git**: сравни `git status --short`/`git log -1` СЕЙЧАС с снимком из плана (шаг 1 записи) — код мог измениться между сессиями (коммит вручную, откат, чужая правка). Если разошлось — сверь план с реальным состоянием, не продолжай слепо по устаревшим «что сделано»/«что осталось».
- [ ] 4. **Durable insight — отдельно**: если при чтении плана/reconcile всплыло что-то, достойное памяти на будущее (не только для этой задачи) — `mb learn`/`mb note new` ЭТО отдельным вызовом, до удаления плана. Сам план — одноразовый оперативный артефакт, он не заменяет постоянную память (см. `mb-memory`).
- [ ] 5. **Удали файл плана** (одноразовый; иначе будет висеть вечно) → продолжай с первого незакрытого шага (скорректированного по reconcile из шага 3).
