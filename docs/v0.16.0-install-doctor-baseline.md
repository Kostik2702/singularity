## 1. What the release closed

The engine could not answer a question about itself: where the tokens go.
`mb usage` reads the client's transcripts — that is, it writes nothing new in
order to get that answer — and gives **two** numbers per step, because any single
one lies.

**What was paid for on the spot** — `usage`, broken down by category (cache read
×0.1, a 5m write ×1.25, 1h ×2, output at its own rate). It finds expensive turns
and is useless for finding leaks: over a long session almost the entire input is
a cache read of the same prefix, and the figure grows monotonically regardless of
what a turn contained.

**What a step added to the prefix and left there** — the difference in prompt size
between neighbouring turns, a subtraction of two reported quantities rather than
an estimate. Hence `carry`: what was added at step *i* is re-read on every
subsequent turn until the next context reset, so a 40k Read at the start of a
400-turn session is not a 40k event, and that price is absent from the bill of the
turn that caused it.

Only the **attribution** of the increment to sources is an estimate (the shares
are proportional to the measured sizes). The report says so where it shows it, and
the shares must **add up** to the measured increment — `unattributed` exists as a
visible line, not as a silent remainder.

## 2. What the baseline checks about this release specifically

Nothing specific. The release touches neither installation, nor the doctor, nor
the config, nor the daemon — it adds one read-only command and fixes a
development tool. This snapshot is here not as a check on a new surface but as a
continuation of the run: it records that adding 1107 lines of domain code, a new
command in the facade, and edits to `tools/plant.py` did not move a single one of
the doctor's forty answers.

What actually was checked about the release was checked by runs against **live**
data, not fixtures: the command read all 7 transcripts on the machine, and on each
one the sum of the sources matched the measured context increment to the token.

## 4. What turned up when the tool was pointed at live data

Worth recording separately, because it is a characteristic of the **method** and
not of the feature: four defects of one shape — each produced a plausible wrong
number, and none would have been visible on synthetic data.

- **The body of a loaded skill** arrives as an ordinary text block in a user
  message and counted as human input: 46.6% of the session's whole context
  increment was signed "user input".
- **A line with `model: "<synthetic>"`** ("API Error: Connection closed
  mid-response") carrying entirely zero usage, counted as a turn, invented a
  580k context reset and an equal growth at the next step.
- **The text of hooks and `<system-reminder>`**, arriving inside user messages,
  was counted as something a human typed.
- **`--list`** applied the display limit before sorting by cost, so the most
  expensive session never opened, and the printed total covered only the surviving
  rows: $190.67 against the real $493.47.

## 5. The gate that could not fail

`tools/plant.py` exists to prove that other people's checks can fail. It reported
GREEN — "this invariant does not catch its own violation" — about invariants that
catch it flawlessly, every time the substituted string preserved the file's
**size** (`0.1` → `1.0`): CPython compares a `.pyc` against its source by the pair
(mtime, size), mtime is stored with one-second granularity, and a plant made
within the same second as the previous compilation executed stale bytecode.

The verdict pointed in the **wrong** direction while doing it: the reader went off
to rewrite a healthy test. The cache is now cleared around both writes — the plant
and the restore — and that is pinned by three tests, each of them proven by
planting a violation.

Recorded alongside as a lesson: the first attempt to verify the fix with a single
case went red both with and without the fix, that is, proved nothing. The bug
reproduces only with a sequence of cases over one file, where restoring the
previous one sets a fresh mtime.

## 6. What this snapshot does not cover

- **Windows.** The run of macOS snapshots is seven in a row; the platform half has
  been unverified since v0.12.0. The new module reads transcript paths through
  `Path.home()` and does not build them from strings, but that was never run on
  Windows.
- **Other clients.** `mb usage` understands only Claude Code transcripts. Gemini
  and Grok, which `mb reflect` already walks, are not supported here — that is the
  feature's boundary, not a gap in the snapshot.
- **The multiple-attempt branch of a request.** A `usage.iterations` longer than
  one never occurred across the machine's 12 transcripts; the code for it is
  written and was only ever run on synthetic data.
- **Promotional tariffs and partner pricing.** The Sonnet 5 intro rate runs until
  2026-08-31 and is deliberately not modelled; Bedrock/Vertex is billed by the
  partner. There is not a single transcript on those models on the machine, so
  none of this touches the release's figures.
- **The Opus 4.8 fast rate** in the table is an extrapolation from Opus 5, marked
  as such in the code: the mode's availability is documented, a separate price is
  not.
