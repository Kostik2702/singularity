# v0.5.0 — baseline на момент релиза

Снято **2026-07-29** сразу после мержа `release/v0.5.0` в `master`
(merge-коммит `97b15f9`, тег `v0.5.0`) на боевом vault. Windows 11 Pro 26200,
Python 3.10, энкодер на CPU.

Назначение — эталон «как было на релизе v0.5.0» для следующего эпика. В отличие
от [code-index-baseline.md](code-index-baseline.md) (срез ДО существования
корпуса кода, задача C00) здесь зафиксировано **финальное состояние всех трёх
корпусов**.

---

## 1. Воспроизведение

```powershell
python tools/code_index_baseline.py capture --both --out docs/v0.5.0-baseline.json
python tools/code_index_baseline.py compare  docs/v0.5.0-baseline.json
python tools/code_index_audit.py             # приватность и состав корпуса кода
mb stats --json ; mb status --json ; mb doctor ; mb selftest
python -m pytest -q
```

Машиночитаемые срезы рядом:
**`docs/v0.5.0-baseline.json`** (10 контрольных запросов × топ-5, обе выдачи —
без кода и с `--with-code`) и **`docs/v0.5.0-baseline-timings.json`**
(тайминги + sha256 вывода четырёх команд).

### ⚠️ Как этим пользоваться

Vault живой: абсолютные `score` и хеши законно меняются от любой новой заметки.
Побайтовое сравнение с этим файлом через месяц ничего не докажет. Эталонными
здесь являются **относительные** величины — доля вытеснения, доля fallback,
порядок таймингов — и метод их снятия, а не конкретные числа.

Хеши из `v0.5.0-baseline-timings.json` годятся ровно для одного: доказать, что
рефактор, сделанный **в пределах одной сессии** без правки заметок, не изменил
вывод `curator`/`digest`/`stats`/`status`.

## 5. Контрольные запросы: вытеснение памяти кодом

Те же 10 запросов, что и в C00, одна сессия, одна переменная (`--with-code`):

| Метрика | Значение |
|---|---|
| Код-хитов в топ-5 | **18 / 50** |
| Вытеснено заметок | **13 / 50** |
| top-1 сменился | **4 / 10** |

Это **не** те цифры, что стояли в C06 (10/50, 4/50, 0/10). Разница — состав
корпуса: вырезан вендоренный SDK, добавлен собственный код Singularity.
Полный разбор и вывод — [code-index.md](code-index.md) §6.

**Практическое следствие для следующего эпика:** цифры вытеснения измеряют
сегодняшний состав корпуса, а не свойство системы. Любое изменение состава
(новый репозиторий, изменение `SKIP_*`, `code_vendored_pattern`) обязано
сопровождаться повторным `capture --both`, иначе решение D2 будет обсуждаться
по устаревшим данным.

## 7. Чего этот baseline НЕ покрывает

* **macOS** — ни одного прогона;
* время полной пересборки корпуса **памяти** (не пересобиралась намеренно —
  в этом был смысл гейта миграции C01);
* поведение при `code_vendored_pattern`, отличном от дефолта, — ключ добавлен
  в этом же релизе и на боевом корне не использовался;
* `mb reflect` и телеметрию — вне периметра этого релиза.
