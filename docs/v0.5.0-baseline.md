# v0.5.0 — baseline at the moment of release

Taken **2026-07-29** right after `release/v0.5.0` was merged into `master`
(merge commit `97b15f9`, tag `v0.5.0`) on the production vault. Windows 11 Pro
26200, Python 3.10, encoder on CPU.

Its purpose is a reference for "how things stood at release v0.5.0" for the next
epic. Unlike [code-index-baseline.md](code-index-baseline.md) (a slice from
BEFORE the code corpus existed, task C00), this records the **final state of all
three corpora**.

---

## 1. Reproduction

```powershell
python tools/code_index_baseline.py capture --both --out docs/v0.5.0-baseline.json
python tools/code_index_baseline.py compare  docs/v0.5.0-baseline.json
python tools/code_index_audit.py             # privacy and composition of the code corpus
mb stats --json ; mb status --json ; mb doctor ; mb selftest
python -m pytest -q
```

The machine-readable slices sit alongside:
**`docs/v0.5.0-baseline.json`** (10 control queries × top-5, both result sets —
without code and with `--with-code`) and
**`docs/v0.5.0-baseline-timings.json`** (timings + sha256 of four commands'
output).

### ⚠️ How to use this

The vault is alive: absolute `score` values and hashes legitimately change with
any new note. A byte-for-byte comparison against this file a month from now
proves nothing. What is canonical here are the **relative** quantities — the
displacement share, the fallback share, the order of magnitude of the timings —
and the method of taking them, not the particular numbers.

The hashes in `v0.5.0-baseline-timings.json` are good for exactly one thing:
proving that a refactor done **within one session**, with no note edited, did not
change the output of `curator`/`digest`/`stats`/`status`.

`mb curator` is the most expensive analysis; that is expected, since it holds a
semantic layer over the whole index. If the next epic touches it, the comparison
must be against 6.5 s, not against "fast".

## 5. Control queries: memory displaced by code

The same 10 queries as in C00, one session, one variable (`--with-code`):

| Metric | Value |
|---|---|
| Code hits in the top-5 | **18 / 50** |
| Notes displaced | **13 / 50** |
| top-1 changed | **4 / 10** |

These are **not** the numbers that stood in C06 (10/50, 4/50, 0/10). The
difference is the corpus composition: the vendored SDK was cut and Singularity's
own code was added. The full analysis and conclusion are in
[code-index.md](code-index.md) §6.

**The practical consequence for the next epic:** displacement figures measure
today's corpus composition, not a property of the system. Any change of
composition (a new repository, a change to `SKIP_*` or `code_vendored_pattern`)
must be followed by another `capture --both`, or decision D2 will be argued from
stale data.

## 7. What this baseline does NOT cover

* **macOS** — not a single run;
* the time of a full rebuild of the **memory** corpus (deliberately not rebuilt —
  that was the whole point of the C01 migration gate);
* the behaviour under a `code_vendored_pattern` other than the default — the key
  was added in this same release and was never used on the production root;
* `mb reflect` and telemetry — outside this release's perimeter.
