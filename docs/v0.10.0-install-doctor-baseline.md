## 1. What the release closed

Not a defect but the **cost of reading**: `mb` had grown to 23 top-level commands
and 60 leaves in one flat list, where four everyday commands sat next to
`uninstall` and `reflect`. The release narrows what the CLI **shows**, moving
nothing behind the showcase.

| What it was | What it became |
|---|---|
| `mb --help` — 23 commands in one list | 10 in the showcase, the full list behind `mb help --all` |
| a bare `mb` — an argparse error (exit 2) | a status line (exit 0) |
| seven neighbouring CLIs mentioned nowhere in help | named in a line in the footer |
| subcommands declared in two styles (`choices` for `daemon`/`index`, `add_subparsers` for the rest) | help shows both identically; the inconsistency itself remains inside |

## 2. Why this is safe — and how the snapshot checks it

A facade is the class of change that looks good in a demo and rots in the cracks:
the group path quietly diverges from the direct one, help lists a command the
parser lost, an exit code changes without anyone deciding. So the new
`v0100_cli_window` section asks exactly that, and its main rows are
**byte-for-byte**, not "does the same thing":

| Check | Result |
|---|---|
| the showcase lists exactly what `facade.WINDOW` declares | OK |
| `mb help --all` names **every** command of the parser | OK |
| `mb service daemon --help` == `mb daemon --help` (stdout byte for byte) | OK |
| `mb setup config --help` == `mb config --help` | OK |
| `mb curator nightly --help` == `mb nightly --help` | OK |
| `mb status stats --help` == `mb stats --help` | OK |
| a host still dispatches to its own command (`mb curator` did not become a listing) | OK |
| exit codes: `mb help` → 0, `mb <unknown>` → 2, `mb service <unknown>` → 2 | OK |

The last row pins the **only behavioural change** in this release, so a later
edit cannot shift it silently: `docs/UPGRADE.md` promises exactly those three
numbers.

## 4. What the snapshot does NOT check

- **The showcase on Windows.** The logic and the exit codes were checked on
  macOS; the previous four snapshots covered Windows, but the `v0100_cli_window`
  section did not exist yet there. The first snapshot on a Windows machine after
  the update will close that too.
- **That the groups are convenient.** Byte-for-byte equality proves the path
  leads to the same command and says nothing about whether a person will find
  what they need. The only measure of that is `mb reflect`, and it now at least
  has a reader (the "Health from the data" section in the `memory-curator`
  skill).
- **Skills on the group paths.** They are not there, by the owner's decision:
  automation stays on the direct paths, which is why the snapshot does not try to
  grade them.
