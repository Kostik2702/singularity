## 1. What the release closed

The repository spoke two languages inside single files, and one of those places
mattered: `machine/routing.py` classified every prompt by matching Russian word
stems, so the workflow router was a function of the user's keyboard. An English
prompt was never routed; a Russian one always was.

Translating the stem list would have flipped the bias rather than removed it, so
the deciding moved to the reader that understands every language. The
`UserPromptSubmit` hook pushes the table of chains once per session and the model
names the class. The push moment did not move — that was the hook's whole reason
to exist — only the deciding.

125,976 characters of non-Latin text left the prose. Several regexes turned out
to be narrower than they looked (`\w` is already Unicode-aware, so a spelled-out
Cyrillic range beside it added nothing while an explicit uppercase class limited
a signal to two alphabets); removing the ranges made those signals hold for every
script.

## 2. What this baseline checks about this release specifically

Two things, and the first is the one a snapshot is for.

1. **The engine still installs and answers the same.** This release rewrote 149
   files, including the shared preamble every subagent starts on, four hooks and
   the CLI's `route` command. Every section here is unchanged from v0.16.0 and
   green: the launcher shims under a shadowing CWD, the locator against a version
   manager, the config write path, the machine config, the CLI window, the
   package layout. A translation that changed installation would show up here.
2. **A new doctor check exists and answers.** `D10-rules-inventory` is PASS at
   `43 of 76 unaccounted, unchanged`. It computes what `rules_delivery`'s
   docstring described in prose; until this release nothing did, which is how a
   rule note sat in none of the three buckets while the inventory "added up".

## 4. One WARN, and why it is not in this file

The first take gave **39 PASS and 1 WARN**: `B7-daemon — running but serving code
older than the files on disk`. The warning was real and the cause was procedural,
not a property of the release: `tests/test_plants.py` mutates real repository
files and restores them, which moves their mtime, and `B7` compares mtimes. A
full suite run immediately before a snapshot therefore leaves the daemon looking
stale even when the modules it serves are byte-identical.

`mb daemon restart` and a re-take gave 40 PASS. The tool's own ordering is
correct — `doctor_report` is evaluated before `run_pytest` — so this is a
sequencing rule for whoever takes the next snapshot rather than a defect:
**restart the daemon immediately before running the tool, not before running the
suite by hand.**

## 5. What this snapshot does NOT check

- **That the router is better.** It records that installation, config and layout
  are unmoved. Whether handing classification to the model produces the right
  class is not measurable here; the evidence for that is `tests/test_routing.py`,
  where the same request in six languages must produce byte-identical guidance.
- **Windows.** The run of macOS snapshots is eight in a row; the platform half
  has been unverified since v0.12.0. This release touched four hooks and the
  installer's skill manifest, so the first Windows snapshot after it is worth
  comparing line by line.
- **The remaining inventory.** `D10` reports 43 of 76 rule notes accounted for by
  nobody. That number is a ratchet, not a target: most of the 43 are the groups
  `NOT_OURS_TO_DELIVER` describes in prose, and turning that prose into 43 names
  is work this snapshot makes visible rather than pretends is done.
- **A clean install.** As in every previous snapshot, `pip install` into a fresh
  environment was not run.

## 6. How to catch a regression

- `D10-rules-inventory` reporting a number above 43 — a rule note arrived that
  nothing delivers and nothing records as out of scope.
- Any `pass: false` in `v0110_package_layout` — the translation moved a module
  and the wheel would ship without it.
- `issue_12_live_config_reload` failing — the hooks were rewritten in this
  release, and this is the section that proves a live daemon still picks up a
  config change.
