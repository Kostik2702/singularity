## 4. What this baseline does NOT prove

- **It was taken on macOS, like v0.6.1.** The Windows branches (the PATH
  registry, the `.cmd` shims, the scheduler branches) did not execute in this run
  at all. Cross-OS coverage of this batch rests on the tests and on the v0.6.0
  snapshot, which was taken on Windows.
- **The single WARN is honest and stays.** `A6-config-paths`: 8 paths belong to
  the Windows machine the vault came from (three projects, `llama.cpp`, three
  `.gguf` files). The values cannot be guessed and the files are not on this
  machine — and since v0.7.0 the doctor finally has something to propose for
  models (`mb llm add` / `mb llm remove`).
- **Not one of the six defects was caught by the matrix** — each was found while
  executing the tool's own output. The `config_write_path` section and the env
  suppression in the locator matrix were added after the fact; they close exactly
  those two classes and were verified against the pre-fix tree.
- **A full clean install was not run.** As in the previous snapshots.

## 5. How to catch a regression

- `config_write_path.cases[*].literal_top_level_keys` non-empty — the v0.6.1
  defect is back.
- `issue_10_cli_locator.suppressed_env` gone — the tool is grading the operator's
  shell again instead of the search order.
- `D5-vault-guard: disabled` without an explicit `vault_guard_enabled: false` in
  the config — the v0.6.3 default was lost (or the hook started its own copy of
  the default again).
- `A6` reporting PASS while the paths are plainly foreign — either `path_entries`
  or `foreign_os` broke.
