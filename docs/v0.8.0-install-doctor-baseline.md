## 4. Чего этот baseline НЕ доказывает

- **Снят на macOS, как и v0.6.1.** Windows-ветки (реестр PATH, `.cmd`-шимы,
  ветки планировщика) в этом прогоне не исполнялись вовсе. Кросс-ОС покрытие
  этой пачки держится на тестах и на снимке v0.6.0, снятом на Windows.
- **Единственный WARN честный и остаётся.** `A6-config-paths`: 8 путей
  принадлежат Windows-машине, с которой приехал vault (три проекта,
  `llama.cpp`, три `.gguf`). Значения нельзя угадать, файлов на этой машине
  нет — и с v0.7.0 у доктора наконец есть, что предложить для моделей
  (`mb llm add` / `mb llm remove`).
- **Ни один из шести дефектов не был пойман матрицей** — каждый нашёлся при
  исполнении собственного вывода инструмента. Секции `config_write_path` и
  подавление env в locator-матрице добавлены задним числом; они закрывают
  именно эти два класса и проверены на дофиксовом дереве.
- **Полная чистая установка не прогонялась.** Как и в предыдущих снимках.

## 5. Как ловить регрессию

- `config_write_path.cases[*].literal_top_level_keys` непустой — вернулся
  дефект v0.6.1.
- Пропало `issue_10_cli_locator.suppressed_env` — инструмент снова оценивает
  оболочку оператора, а не порядок поиска.
- `D5-vault-guard: disabled` без явного `vault_guard_enabled: false` в конфиге —
  дефолт v0.6.3 потерян (или хук снова завёл свою копию дефолта).
- `A6` со статусом PASS при заведомо чужих путях — сломалась `path_entries`
  либо `foreign_os`.
