## 1. What the release closed

An inventory of the vault's 73 rule notes showed that **37 rules out of 72 were
delivered nowhere** — they fired only if somebody already knew what to look for.
And worse: `AGENT_SHARED_PREAMBLE` — the rule set every subagent starts on — was
read from the path `{{VAULT}}/rules/`. The behaviour of eight agents was a
property of which vault was configured: a move, a swap or an empty vault left
them with no rules at all, silently.

The boundary this release draws: **knowledge in the vault, mechanism in the
engine**. Losing the vault must cost recall and nothing else.

- the preamble moved to `singularity/agents/`, is deployed together with the
  agents, and is addressed by a new `{{AGENTS}}` token;
- two SessionStart fragments for the main thread, which has no preamble (memory =
  the vault, and writes through `mb`; a rule acts at the point of decision) —
  747 → 1142 tokens per session;
- nine rules were grafted into the preamble, twelve into nine skills;
- `rules_delivery.py` holds a registry of 31 injections and fails the suite when
  any of them disappears; `WITHOUT_A_POINT` and `NOT_OURS_TO_DELIVER` stop an
  untouched rule hiding behind "probably covered somewhere".

**The registry proved itself before the release.** Merging v0.12.0 into the branch
turned it red: deleting `reel` took both delivery points of the `aeval` envelope
rule at once. That is the only reason its entry now sits in `WITHOUT_A_POINT`
rather than being invented into a neighbouring skill.

## 2. Line-by-line comparison with the previous snapshot (Windows → macOS)

The v0.12.0 summary ended with a request: compare the next macOS snapshot line by
line, because the platform divergence had turned out not to be theoretical there.
Done: **25 divergences out of 352 paths**, and not one of them is a regression.

| What | Windows v0.12.0 | macOS v0.13.0 | Why |
|---|---|---|---|
| `doctor` | 37 PASS + **1 WARN** | **38 PASS** | the WARN was `B7-daemon` — the daemon was serving code older than the files on disk. Here it was restarted before the snapshot |
| pytest | 2044 passed, 15 skipped | 2060 passed, 25 skipped | different platform sets; 2060 = 2061 − 1, the tool excludes `tests/test_gemini_e2e.py` |
| `A6-config-paths` | 6 paths | 2 paths | the machine's composition: on Windows there lived `llm.server_bin`, two models and three projects |
| `K1-code-index` | 7661 chunks / 2035 files | 3441 / 271 | different corpora, not different behaviour |
| `suppressed_env` | — | `NVM_BIN`, `NVM_DIR` | the locator isolates what is actually in the environment |
| launcher stdout | `mb 0.12.0` | `mb 0.13.0` | the version |

The divergence in `skipped` (15 → 25) is the place where our own rule says to
grow suspicious: a rise in skips means checks were switched off. Here it is
platform-based (Windows specifics do not run on macOS), not acquired: within one
machine the counter has stood at 25 for the whole release cycle, including the run
after the v0.12.0 merge.

## 3. What new thing this snapshot is even able to ask

The release is about dependency, so the weight moved onto the sections that
resolve paths and read the config: the machine's behaviour no longer has the right
to change along with which vault is configured.

`package_layout` carries the structural half: the deployed preamble is a real
engine file that travels with the agents, not a note somebody reads out of
`{{VAULT}}/rules/` at start-up. The check that it stayed that way does not live
here but in the suite: `test_no_agent_reads_its_rules_out_of_the_vault` and
`test_agents_dir_token_resolves_without_a_vault` — the second deliberately renders
the token for a vault that does not exist.

## 4. What this snapshot does NOT check

**It does not check that the model followed the rule.** The registry grades the
presence of text at a point: the marker is there, so the rule was delivered.
Whether the model reads it and whether that changes its behaviour, the snapshot
cannot say, and `all_pass: true` should not be read more widely.

**It does not grade a machine with no vault.** The claim "the rules work whatever
state the vault is in" is checked by a unit test on a substituted path, not by
taking a snapshot on a machine where the vault really is absent. That remains an
honest hole: nobody has run a live `mb doctor` on a vault-less machine.

**It says nothing about the four groups of rules the engine does not deliver** —
those of other projects (singularity-ui), of the video engine, the dormant Windows
specifics, and the code invariants. They are written down in
`NOT_OURS_TO_DELIVER` with reasons, but their execution lives in other
repositories and by other means.

**And it does not grade a second machine.** The snapshot was taken on macOS; the
previous one on Windows, where `B7-daemon` was a WARN. The next Windows snapshot
is worth comparing against this one by the same table in §2 — especially the
`doctor` row, because the only behavioural divergence between the platforms in
this cycle was exactly there.
