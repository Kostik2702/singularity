# v0.12.0 — baseline 2026-08-05 (removing a subsystem, not adding one)

Taken on master `5b24344` — the tree that contains the code being assessed.
Production vault, **Windows 11 (10.0.26200)**, Python 3.10.6, vault
`E:\obsidian\memory brain`.

**The `v0.12.0` tag sits two commits later, on `9e47803`, and that is not
carelessness.** The snapshot revealed that two sources of the version had
diverged in the release tree: `pyproject.toml` already said 0.12.0, while
`singularity/__init__.py` still said 0.11.2. The tag was moved to the tree where
they agree and where the invariant that now catches this lives
(`tests/test_version_sources_agree.py`, verified by planting the divergence). The
difference between the snapshot and the tag is three files: the snapshot itself,
its summary, and that test; the code being assessed does not change in them.

The same tool (`tools/install_doctor_baseline.py`), the **eighth snapshot in a
row**, the fourth on Windows. `all_pass: true`.

Machine-readable slice: **`docs/v0.12.0-install-doctor-baseline.json`**.

---

## 1. What the release closed

For the first time a release **removes** a subsystem rather than adding one.
`singularity/reel` — a Python editing pipeline written before `video-engine` —
was deleted entirely: 14 modules, a console command, the shims, the tests, the
entry point, a ruff exclusion, and the `reel-editor` skill.

The reason is not code quality but that a fallback path **decides the
architecture for you**. Asked to cut a clip, one picks the tool that runs, not
the one the map points at: a full-length clip was assembled by `reel` even though
`video-engine` had twice been named as the target. The video system's map lists
three tools — `capcut-bridge`, `video-engine`,
`video-effects-motion-service` — and `reel` was in none of them.

## 2. How this snapshot differs from the previous one

**The surface is smaller, deliberately.** The `issue_9_16_launchers` and
`issue_10_cli_locator` sections grade one launcher fewer. The key one here is
`v0110_package_layout`: it proves the removal is **complete**, rather than "the
package is gone but the tails remain".

The tails were found by the test suite, and this is the case invariants are
written for:

- `reel.util` remained in the presentation layer's EXEMPT list — caught by the
  check that "every exception must exist". The list got shorter, which is the only
  direction it is allowed to move in;
- `reel-editor` remained in the skill manifest with no folder in the repository —
  caught by two checks at once.

**And one defect older than this release.** The architecture scan identified skill
scripts by the check `"/skills/" in str(f)`. On Linux that is true; on Windows it
is false — the path contains `\skills\`. That is, **three invariants passed on one
platform and failed on another for the same tree**, and on this machine
standalone skill scripts fell into the engine-module scan and were accused of
printing outside the presentation layer — the very thing such a script exists to
do. Comparing by path components makes the invariant identical everywhere.

## 3. The remaining sections

All eight `pass: true`. `issue_11_13_14_15_doctor`, `issue_12_live_config_reload`,
`config_write_path`, `v090_machine_config` and `v0100_cli_window` were not touched
by this release and were taken as a control: removing a subsystem should not have
affected them, and it did not.

The tests inside the snapshot: **2044 passed, 15 skipped, exit code 0**. The
number is one lower than a direct run gives (2045), for two reasons that add up:
the tool ignores `tests/test_gemini_e2e.py`, which needs a real CLI, and the
parametrised case `[reel.util]` disappeared along with the module. **There are as
many skips as in v0.11.0 and after** — a rise in the number of skips would mean
checks had switched themselves off, which is why it is checked rather than merely
printed.

## 4. What this snapshot does NOT check

**It says nothing about video editing.** The snapshot grades installation, the
config, the locator, the CLI window and the package layout — that is, the memory.
The capabilities that left with `reel` live in another repository and are not
measured by this tool:

| what left | where it is now | state |
|---|---|---|
| `build` | `video-engine render` | closed |
| `bed` + `mux` | `video-engine`, the `audio` block in the timeline | closed |
| `beats` / `sections` | `capcut-bridge tempo --sections` | closed |
| `probe` / `sheets` | `capcut-bridge intake` / `survey` | closed |
| `match`, look, grain, vignette, dissolves | — | **not closed**, task `VIDEO-ENGINE-EFFECTS` |
| `qa` — counting flashes per WCAG on a rendered file | — | **not closed**, task `ENGINE-QA-GATE` |

The last row is the only gate in the whole pipeline with a medical rather than a
taste-based boundary, and right now it has no tool. The snapshot does not see this
and cannot; it is said here so that `all_pass: true` is not read more widely than
it is.

**The snapshot also does not grade a second machine.** It was taken on Windows;
the previous three were on macOS. With this release the platform divergence turned
out for the first time not to be theoretical (see the scan defect in §2), so the
next snapshot on macOS is worth comparing line by line.
