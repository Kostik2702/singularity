The same tool (`tools/install_doctor_baseline.py`), the **thirteenth snapshot**,

## 1. What the release closed

`mb code`: a structural code graph of the owner's repositories — who calls
what, what a change reaches, what is never called, how the code falls apart
into parts, and one read-only SQL. The engine's own (tree-sitter extractors,
import-aware resolvers, one SQLite graph per unit in transactional
generations), refreshed before every query and proven equal to a full build
by a random-edit oracle. Off until `code_graph_enabled`; `mb search` does not
depend on it. The CHANGELOG has the whole release.

The tag moved once. `v0.18.0` was first pushed on `871c699`; the CI matrix,
which had not started a single job since v0.16.0 (the account's billing), ran
for the first time on it and failed on all nine jobs. The fixes — tests,
tools and one installer assuming the machine they were written on, and one
product defect in the Windows directory locks — went in before this snapshot,
the matrix went 9/9 green on `3adf7e6`, and the tag was moved there.

## 2. What this baseline checks about this release specifically

1. **The engine still installs and answers the same, on the other OS.** Every
   section that was PASS on macOS for v0.17.0 is PASS here on Windows: the
   launcher shims under a shadowing CWD, the locator against a version
   manager, the config write path, the machine config, the CLI window, the
   live config reload through the daemon. v0.17.0's baseline asked for exactly
   this: "the first Windows snapshot after it is worth comparing line by line".
2. **The new package ships.** `v0110_package_layout` now also requires
   `singularity.codegraph` and `singularity.platform` to be discovered by
   setuptools, and imports `codegraph.sidecar` (read by the SessionStart hook
   on every session — a wheel without it breaks the first session, not a
   command) and `platform.fslock` (every writer lock goes through it now).
   All discovered, all import.
3. **A new doctor check exists and answers.** `K2-code-graph` is WARN with a
   reason (§4), which is the check doing its job, not failing it.

## 4. Seven WARNs, and whose each one is

- **`K2-code-graph`** (new in this release): 9 graphs, 1856 files, 38 MB, and
  8 secret-shaped values in the Singularity graph — the fake keys in
  `tests/test_redact.py`'s parametrize decorator and a `ghp_` string in
  `tests/test_cli_learn_note.py`. The audit is right that they are key-shaped;
  whether test fixtures may be allowlisted is the owner's decision, and until
  it is made the check says so on every run.
- **`E3-gemini-skills`, `F3-grok-skills`**: `mb-code`, the release's new
  skill, is registered for every client in `install/skill_manifest.py` but not
  yet deployed on this machine for Gemini and Grok (`install/register_gemini.py`,
  `install/register_grok.py`). Claude has it. A deployment step on this
  machine, not a defect of the release.
- **`A6-config-paths`**: two configured paths do not exist here
  (`llm.models.bonsai27b.gguf`, `projects.vibe24.path`). Machine config.
- **`E1-gemini`, `E4-gemini-hooks`**: the `gemini` binary is unreachable from
  a non-interactive process on this machine. Machine state.
- **`D10-rules-inventory`**: 63 of 111 rule notes delivered nowhere and
  recorded as out of scope nowhere (v0.17.0: 43 of 76). Vault content: the
  count grew with the vault, the check is what makes it visible.

As in v0.17.0, the daemon was restarted immediately before the tool ran, so
`B7-daemon` is PASS: a suite run moves source mtimes, and B7 compares them.

## 5. What this snapshot does NOT check

- **macOS and Linux.** This snapshot is one Windows machine. The other two
  platforms are covered by the CI matrix going green on the tagged commit,
  which grades the suite, not an installation.
- **The code graph's behaviour.** Only that its package ships, its hook-side
  reader imports and its doctor check answers. Correctness is the oracle
  (`docs/code-graph-p3-oracle.json`), precision the yardstick
  (`docs/code-graph-yardstick-baseline.json`), the deadcode audit
  (`docs/code-graph-p4-deadcode-audit.json`), and the chunker v2 gate
  (`docs/search-eval-code-v2.json`).
- **A clean install.** As in every previous snapshot, `pip install` into a
  fresh environment was not run; the layout section is the proxy for it.

## 6. How to catch a regression

- `K2-code-graph` naming more than the 8 test-fixture findings — a real
  secret-shaped value reached a graph.
- `D10-rules-inventory` above 63.
- Any `pass: false` in `v0110_package_layout`, in particular the
  `singularity.codegraph` row or the `codegraph.sidecar` import.
- A red CI job on any OS. The matrix runs again; the release that tagged a
  red matrix is the reason this line exists.
