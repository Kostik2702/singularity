## 1. What the release closed

Not a defect but an accumulated shape: 10 263 lines (43% of the engine) lay flat
in `singularity/`, `cli.py` had grown to 1 511 lines, and about 300 `print`
statements lived inside domain modules, which for that reason neither the daemon
nor a hook could use. Plus three tails of the 2026-07 audit, marked PARTIAL and
left open.

| What it was | What it became |
|---|---|
| the package root: 31 modules mixed together | 10 files + `knowledge/` `machine/` `telemetry/` `commands/` |
| `cli.py` at 1 511 lines | 523 lines (parser + dispatcher) |
| `load_config` called `sys.exit` | `ConfigError`; the daemon no longer needs its own copy of the validation |
| the report printed from inside the domain | the collector returns data, `render.py` formats it |
| 9 import cycles | 0 |
| AUD-17 / AUD-18 / AUD-21 open | closed |

## 4. What this snapshot does NOT check

- **A real `pip install` into a clean environment.** The section grades package
  *discovery* and imports from this tree; it would have caught a forgotten
  subpackage, but not, say, a data file missing from the wheel. The first install
  on a second machine remains the honest check.
- **The layers on Windows.** The invariants (`test_architecture`) are
  platform-neutral and run in the suite, but the snapshot was taken on macOS.
- **That the new capabilities get used.** `mb inbox`, `--hybrid` and the daemon
  counters are covered by tests and live runs, but whether they stay in daily use
  is a question for `mb reflect`, not for a baseline.
